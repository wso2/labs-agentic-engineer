> **Rationale:** Public API for events, proposals, scoring and registrations (stories 1-15); calls registration-service (build-order edge); gated on events-db and user-auth provisioning.

## Scope
Implement the Ballerina events-api per specs/design/components/events-api/design.json and openapi.yaml: events, rooms, sessions (with seatsRemaining/waitlistCount from registration-service), proposals, once-per-reviewer scoring (1-5, average), decisions, scheduling an accepted proposal into a session (sets capacity in registration-service; rejected proposals cannot be scheduled), and caller-facing /me/registrations operations delegating to registration-service with the caller's token (enforce event registration before session registration). Enforce scopes per specs/design/security.json. Persist in events-db (platform-resource gate) ; user-auth thunder-app is a platform gate. Depends on registration-service for the build-order edge.

No flow: backend API, no views.

## Acceptance
- All openapi.yaml operations implemented with the declared scope checks and error codes.
- Registration state never stored locally.
- bal build && bal test pass.
