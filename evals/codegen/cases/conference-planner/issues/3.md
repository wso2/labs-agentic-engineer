> **Rationale:** Single SPA for all four roles (stories 1-15) calling events-api (build-order edge); gated on user-auth thunder-app provisioning.

## Scope
Implement the React SPA per specs/design/components/conference-webapp/design.json, honouring wireframes.dsl screen for screen. Calls only events-api (openapi.yaml); sign-in via Thunder SSO (user-auth thunder-app platform gate); role-based navigation per security.json. Oxygen UI design system.

Screens: Events, EventDetail, MyRegistrations, MyProposals, SubmitProposal, ReviewQueue, ReviewProposal, ManageEvents, EventForm, EventAdmin, RoomForm, SessionForm, SessionRegistrations, OrganizerProposals, ProposalDecision

Flows:

- [ ] **F1 · Browse and register**
  An attendee browses events, registers and checks their status
  Persona: Attendee
  Stories: 9, 10, 11, 12, 13, 14
  Walk: Events → EventDetail → MyRegistrations
- [ ] **F2 · Submit a talk**
  A speaker submits a proposal and follows its outcome
  Persona: Speaker
  Stories: 4, 5
  Walk: MyProposals → SubmitProposal
- [ ] **F3 · Score proposals**
  A reviewer scores proposals
  Persona: Reviewer
  Stories: 6
  Walk: ReviewQueue → ReviewProposal
- [ ] **F4 · Build the program**
  An organizer sets up events, rooms and sessions and watches registrations
  Persona: Organizer
  Stories: 1, 2, 3, 15
  Walk: ManageEvents → EventForm → EventAdmin → RoomForm → SessionForm → SessionRegistrations
- [ ] **F5 · Decide proposals**
  An organizer accepts or rejects proposals and schedules accepted ones
  Persona: Organizer
  Stories: 7, 8
  Walk: OrganizerProposals → ProposalDecision → SessionForm

No flow: none — stories 1–15 are all walked above (sign-in/out is owned by platform SSO; waitlist promotion, story 13, is shown via MyRegistrations status).

## Acceptance
- Every screen and flow above is reachable and works against events-api.
- Build passes; mock-mode walk of all flows.
