> **Rationale:** Build-order edge to procurement-api; gated on platform resource user-auth (thunder-app).

## Scope
Implement the React SPA per specs/design/components/procurement-webapp/design.json and wireframes.dsl, using the Oxygen UI design system, signing in via Thunder SSO (user-auth, platform-resource gate platform-authored). Calls only procurement-api (see its openapi.yaml); role-specific navigation per sidebar.

Screens: Catalogue, NewRequest, MyRequests, MyRequestDetail, ApprovalQueue, ReviewRequest, ReceivingQueue, ReceiveGoods, StockLevels, ItemLedger, LowStock, ManageCatalogue, ItemForm

Flows:

- [ ] **F1 · Browse and request**
  A requester browses the catalogue, raises a request and follows its status
  Persona: Requester
  Stories: 1, 2, 3
  Walk: Catalogue → NewRequest → MyRequests → MyRequestDetail
- [ ] **F2 · Approval queue**
  An approver reviews pending requests and decides them within the approval limit
  Persona: Approver
  Stories: 4, 5, 6
  Walk: ApprovalQueue → ReviewRequest
- [ ] **F3 · Receive goods**
  A clerk receives goods against approved orders and checks stock
  Persona: Warehouse Clerk
  Stories: 7, 8, 9, 10
  Walk: ReceivingQueue → ReceiveGoods → StockLevels → ItemLedger → LowStock
- [ ] **F4 · Manage catalogue**
  A clerk adds new items and edits existing ones
  Persona: Warehouse Clerk
  Stories: 11, 12
  Walk: ManageCatalogue → ItemForm

No flow: sign-in/sign-out (platform SSO owns the page). Story 8 (ledger entry on every stock change) is a backend rule, visible only via the ledger in F3.

## Acceptance
- Every screen and flow above is implemented and walkable in mock mode.
- Build and lint pass; role gating matches security.json.
