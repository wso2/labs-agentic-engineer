> **Rationale:** Owns items, stock levels and ledger (stories 1, 2, 7-12); leaf in build order, with a platform-resource gate on inventory-db (postgres-cnpg).

## Scope
Implement the Ballerina inventory-service per specs/design/components/inventory-service/design.json and openapi.yaml: items (create with 0 on hand, SKU assigned by service, edit name/unit/unitPrice/reorderLevel), stock levels, low-stock (onHand < reorderLevel), per-item ledger (newest first), and POST /stock-movements (idempotent by reference, 409 on repeat, ledger entries written atomically with level change). Persist in inventory-db (platform-resource postgres-cnpg; provisioning gate is platform-authored, no Task). Does not know requests or users; only the procurement API calls it.

No flow: backend service, no views (stories 1, 2, 7-12 are served via procurement-api/webapp).

## Acceptance
- All openapi.yaml operations implemented with the documented status codes.
- Receipt is atomic and idempotent; low-stock excludes items at reorder level.
- bal build && bal test pass.
