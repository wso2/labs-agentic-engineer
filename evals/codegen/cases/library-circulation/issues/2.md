> **Rationale:** Build-order edge to catalogue-service; gated on provisioning of platform resources user-auth (thunder-app) and circulation-db (postgres-cnpg).

## Scope
Implement circulation-api in Ballerina per specs/design/components/circulation-api/design.json and openapi.yaml. Proxy catalogue reads and librarian catalogue management to catalogue-service; implement loans (14-day due date), holds queue (one per title, only when no copy available, first come first served; ready on return), fees (0.25/day computed at return, mark paid), rules (5-loan limit, no borrowing with unpaid fees), /me/ operations scoped to the caller's subject. Update copy status in the catalogue on checkout, return, hold. Enforce scopes per specs/design/security.json (gateway assertion; see thunder-authentication and api-management skills). Gates (flagged, not Tasks): platform resources user-auth (thunder-app) and circulation-db (postgres-cnpg). No background jobs.

No flow: backend service, no views (stories 1–13 served via the API).

## Acceptance
- All operations in openapi.yaml implemented with required scopes.
- Borrowing, hold, return and fee rules behave as in the design description.
- Members never see others' loans/holds/fees.
- bal build && bal test pass.
