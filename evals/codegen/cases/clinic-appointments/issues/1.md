> **Rationale:** Single backend serving all stories; gated on user-auth and clinic-db platform resources provisioning.

## Scope
Implement the Ballerina service per specs/design/components/clinic-api/design.json and openapi.yaml: slots (browse, publish, remove own unbooked), appointments (own and any: list, book, reschedule, cancel), check-in (same-day only), doctor schedule, visit notes (doctor-only, own appointments only).

Rules: transactional no-double-booking against clinic-db; 2-hour cutoff for cancel/reschedule (patients and receptionists); same-day check-in; per-operation scope gating per security.json; ownership checks (404 for other doctors' appointments/notes).

Platform-resource gates (flagged, not Tasks): user-auth (thunder-app) and clinic-db (postgres-cnpg) must be provisioned.

No flows (backend service, no views). Stories served: 1-13.

## Acceptance
- Every operation in openapi.yaml implemented with the specified status codes and scopes.
- bal build && bal test pass; business rules covered by tests.
- Gateway assertion verified per pinned skills.
